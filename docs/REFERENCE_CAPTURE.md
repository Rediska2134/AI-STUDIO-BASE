# Visual Reference Capture

Use this file during live reference sessions. The purpose is not to collect pretty websites; it is to convert specific reactions into reusable design rules.

## How to capture a reference

For each useful reference, record only what matters.

### Reaction

- **What is strong here?**
- **What specifically do we like?**
- **What do we dislike / want to avoid?**

### Reason

Why does the chosen element work?

Possible dimensions:

- hierarchy;
- typography;
- composition;
- spacing;
- navigation;
- sidebar / drawer behavior;
- visual density;
- surface / shadow / border treatment;
- product presentation;
- animation / transition;
- microinteraction;
- responsive transformation;
- commercial clarity / conversion.

### Extracted rule

Write one concrete rule we can actually use. Avoid vague statements such as “looks premium”.

Good:

> Product cards use restrained metadata and reserve the strongest type weight for the product name / primary price, keeping badges visually secondary.

Bad:

> Make product cards cool and premium.

### Scope

Choose one:

- `studio-global` — candidate for future projects;
- `project-local` — only this client/project;
- `experiment` — worth prototyping but not yet a rule.

## Session workflow

During a calibration session:

1. Open references quickly; do not analyze every page completely.
2. Point to the exact element that creates the reaction.
3. Describe what you like in ordinary language.
4. Convert that reaction into a specific rule.
5. Mark whether the rule is global, project-specific, or experimental.
6. Prototype the most important rules in a runnable screen.
7. Review the live result, not just the source reference.
8. Promote only validated repeated preferences into `STUDIO_DESIGN_SYSTEM.md`.

## Anti-copy rule

Never treat a whole third-party site as a design specification. References are ingredients. Preserve the client's identity, content needs, information architecture and commercial goals.
